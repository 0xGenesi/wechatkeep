## 0. 立项基线与目标修正（98 轮实弹的诚实清点）

**98 轮实弹已交付的（v3 原始动机的主体）**：runtime 层在实时撤回路径上
——`keep_message`（newmsgid 清零→消费簇 svrid 查找未命中→零写入→原消
息行不动）+ `tip_text`（replacemsg 改写→系统通知位照常渲染）——私聊
两轮实弹**消息保留+自定义灰条提示同时成立**。77 续㊳ 写模型终裁的
「三选二无解」约束的是**单行补丁**（灰条=撤回态消息行本身）；runtime
层的清零+改写组合天然绕开了它（行不动+通知位独立渲染）。

**v3 残余价值（立项范围据此收缩为两块）**：

- **R-A（门，廉价）**：群聊实弹未验。98 两轮均为私聊（jen/joy）；群聊
  撤回 sysmsg（带群字段/@语义）是否走同一 parse+同语义，一次实弹即知。
  **若群聊同样成立，v3 的用户可见目标已被现有层覆盖**——本项目降级为
  语义升级性质。
- **R-B（本体，语义升级）**：克隆消息行。清零方案的本地 DB 态=「消息
  在但撤回态从未落行」——重同步/搜索/引用/多端长期一致性未长期实证；
  且克隆形态解锁清零给不了的语义：克隆行可标注（如「[已保留]」）、与
  重编辑记账（revokemessage 链）正交、撤回态行与保留态行并存。

## 1. 机械设计（对位基础全在册）

**形态降维（T6 关账带来的）**：原设计「代码洞 shellcode 磁盘注入」（77
续㊳——当时进程内武装已死，只能磁盘改）。现在 runtime hook 已在实时
路径武装（97 修正链，98 实弹），**克隆从 hook 体内直调宿主函数指针
（base+off 解析，同 hook_off 机制）即可，零代码洞**。

**时序安全**：hook 挂 parse **入口**——hook 体先于消费簇的撤回写执行。
克隆 = hook 体内同步**读**原行（捕获内容）→ 异步**插**克隆行（捕获的
内容，非再读）。撤回写在 parse 返回后才发生，只写原行；克隆行携带独立
svrid/rowid 不受波及。插入落队时机晚于撤回写也安全（内容已捕获）。

**既有拓扑入口（直接复用）**：
- 消费簇主函数 0x31a96d8；svrid 查本地消息 0x32edaec+0x309ac50
  （result[obj+0x278] 位=命中）；消息对象取用 0x102b740（shared_ptr
  [+0x6b0/+0x6b8]）；撤回标记写（删/提示合一）0x4cd5e8c（77续㊳）。
- 存储家族：表注册 0x4190130 / SELECT 0x4195490 / INSERT 0x4195ca0 /
  清理族 0x4196130/0x4196650；行插入链 0x3a7a040→0x3aa8590→0x3aaae70
  →0x4195ca0（=revoke-data 表 AddRevokeData，**非**消息表插入——消息
  行克隆需要消息存储族，M1 对位目标）（75 轮增补）。
- 快路存储族/撤回链终版判读：MAINTAINING「270135 撤回链地图·终版判读
  +快路存储族」（74 轮）；Windows 孪生对位表（WINDOWS-SPIKE）。

## 2. 里程碑

- **V3-M0（门，用户窗口）——已关账（2026-10-31 深夜）**：群聊对端撤回
  实弹。**判读：部分成立**——①「群聊独立路径」假说**证伪**：同一
  parse（zero+1 首见清零，消息保留 ✓）；②**tip 群聊不渲染**（用户肉眼
  实证无提示）。②的机械解释**无需新 RE——74 轮终版判读早已预言**：
  群聊 tip=渲染期从 +0x278 载荷生成（0x55139e0 GetRevokeMessage），载荷
  唯一附着点=CoCheck Phase3 按 key 查 revokemessage 行命中（0x55132f0
  附着）；清零→行查找不匹配→无载荷→无 tip+消息不受影响（74 轮「v1
  自洽复验」行的活体复现）；私聊 tip=服务器 in-band type-10000 独立于
  本链（故照常出）。**三选二在群聊成立，但方向修正**：约束不在「行删
  除」——74 轮已证 4.x 全链**不存在原消息行 DELETE**，撤回显示效果=
  revokemessage 行+内存载荷+渲染期 tip，原行从未动。**v3 克隆对象随之
  修正**：「克隆 DB 行」前提失效 → 真问题=**渲染层双态**（内容气泡的
  抑制机制 vs tip 渲染是否同键；同键则须对象/行克隆制造一态副本）。
  附带：自撤 26 payload 走 selfskip 原生放行正常（无缺陷）。
- **V3-M1（RE）**：消息行插入面对位——消息存储族 INSERT（非 revoke-
  data 表）、消息 ORM/模型对象构造（优先 ObjC 层 addMsg 家族，次 C++
  WCDB 直调）、克隆行最小列集、svrid/rowid 冲突面（偏移空间 vs 复合
  键）、线程/队列上下文（消息服务队列亲和性证据）。产出对位表+调用
  约定（对象生命周期/引用计数逐项）。
- **V3-M2（原型缝）**：runtime dylib 内独立实验开关（默认关）——hook
  体内：同步读原行→异步插克隆→放行。副本 E2E：撤回实弹三态可见
  （tip 灰条+克隆内容气泡）+ launch_soak 零新崩。
- **V3-M3（产品化）**：config 键 `clone_message`（默认 off，与
  keep_message/zeroing 三通道关系裁决：克隆开启时清零是否让行）+自撤
  不克隆（selfskip 先于克隆判定）+重编辑记账对齐+FuzzParseSurfaces
  负控（坏 XML 不触发插入）。
- **V3-M4（实弹）**：用户窗口群聊+私聊双实弹验收 + 长期多端重同步
  观察（克隆行存活性）。

## 3. 风险登记

| # | 风险 | 缓解 |
|---|---|---|
| 1 | C++ ABI 直调：对象生命周期/shared_ptr 引用计数/隐参 sret | M1 优先 ObjC 层入口；C++ 直调逐项列调用约定，透传契约缝（revoke_wrapper_hook 全寄存器保存）是结构前提 |

| 4 | 同步语义：伪造 svrid 的克隆行被服务器重同步清理/判孤儿 | M1 svrid 冲突面对位；M4 长期观察；最坏=本地行带标注的「随取随灭」语义 |
