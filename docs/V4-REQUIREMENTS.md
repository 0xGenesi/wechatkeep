## 1. 专家会做而本仓未做的（按价值排序）

1. **合成撤回 oracle（消掉账号舞蹈）**：专家不会靠人工双账号撤回测试——
   会把捕获的 XML 语料（var/wxarm/d*_parse_*.xml，16 条）**直接喂给 parse
   函数**（out-of-process 调用，复用 Verifier mini-loader 技术），断言输出
   struct 的不变量（newmsgid 提取、replacemsg 透传、自发判别门）。确定
   性、可回归、CI 可跑——T5 的「人工窗口」依赖就此退役。**本仓已有全部
   零件**（mini-loader + 捕获语料 + funcSize 校验过的函数边界），只差组装。
2. **UI 级端到端断言**：肉眼观察（灰条有无/文案）换成 Accessibility API
   （AXUIElement 遍历聊天气泡）+ 截图 OCR——「提示显示了什么」变成机器
   可断言。macOS AX 对微信 Qt 界面覆盖度需先探（AppleScript UI 元素枚举）。
3. **配置通道安全模型**：runtime.json 在微信可写的共享容器里（在案），
   专家会做配置签名或至少 mtime/哈希漂移告警（marker 带 cfg_hash=）。
4. **结构化可观测性**：marker/boot log 轮询换成 os_log 统一日志
   （`log stream --predicate`），加 signpost 计时——现场排障从「等 30s
   tick」变实时流。
5. **崩溃先验监控**：利用已有 launch_soak 的 .ips 对照做常态轻量巡检
   （发版外周期跑），把「零崩溃」从发版门变运行门。

## 3. 外部客观标准（L7/L8 增补 + 既有引用）

- **L7 合成 parse oracle**：16 条语料 ×（他人/自发 × 群/私）断言——
  他人：newmsgid 数值提取正确、replacemsg 逐字节透传、keep/zero 门行为
